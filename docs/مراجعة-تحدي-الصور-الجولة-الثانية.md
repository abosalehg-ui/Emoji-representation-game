## 0. تحديد نوع اللعبة والمحرك

| البند | القيمة |
|---|---|
| **التقنية** | JavaScript خام (Vanilla ES Modules)، بدون محرك ولا مكتبات ولا اعتماديات تشغيل |
| **نوع اللعبة** | **ألغاز لفظية (Rebus)**: تفك عبارة عربية (مثل، حكمة، آية، حديث، بيت شعر) من سلسلة أيقونات |
| **نمط اللعب** | **فردي وأوفلاين (PWA)**: بدون خادم ولا حساب ولا لوحة نتائج. فيه «تحدي اليوم» بشبكة مشاركة نصية |

**المعايير اللي ما تنطبق هنا:** ما فيه حلقة لعب بإطارات، فلا Delta Time في الحركة ولا Object Pooling ولا تصادم. وتعديل `localStorage` في لعبة فردية أوفلاين يعتبر غشًّا على النفس، مو ثغرة. ولا يوجد شيء يكسبه اللاعب لو سرّع الوقت.

**المعايير اللي أطبقها بصرامة:** سلامة دورة السؤال وحالاتها الحدّية، وصدق ما يحفظه التطبيق (الجلسة والسلسلة وشبكة المشاركة)، وصمود الأوفلاين لأنه وعد الـPWA، ووضوح الواجهة على الجوال.

## 1. المراجعة التقنية والهندسية (40%): **8/10**

### أ) دورة اللعب والأداء: 8.5/10

الأساسيات صارت سليمة، وهذا يُحسب للمشروع:

- `js/timer.js`، في `startTimer()`: الوقت يُحسب من فارق `performance.now()` الحقيقي، فما ينحرف المؤقت ولا يتجمد في التبويب الخلفي. ولو رجع اللاعب للتبويب بعد ما انتهى الوقت، تنتهي المهلة فورًا ولا ينفتح باب لتسريع الوقت.
- `js/confetti.js`: السرعات بالبكسل لكل ثانية، و`dt` محدود بـ`0.05`.
- `js/game.js`: كل المؤقتات تمر عبر `later()` و`cancelPending()`، و«قفل الإرسال» (`submitting`) يمنع احتساب الإجابة مرتين.
- `js/main.js`، في `boot()`: صار الـsprite تحسينًا وليس شرطًا للإقلاع (`Promise.race` بمهلة 1.2 ثانية)، فما تتعطل اللعبة إذا تأخر طلبه.

**لكن قفل الإرسال فيه ثغرة دخلت مع زر الخروج الجديد:**

#### 🟠 الخروج خلال 700ms بعد آخر حياة يمسح الجولة ونتيجتها

`js/game.js`، في `onWrong()` (ونفس النمط في `handleTimeout()` و`skipQuestion()`):
```js
if (gameState.lives <= 0) {
    later(endGame, TIMINGS.beforeGameOver);   // 700ms
    return;
}
```
و`abandonRound()` يلغي كل المؤقتات المعلقة **ومنها `endGame`**، وبعدها يحفظ الجلسة:
```js
export function abandonRound() {
    cancelPending();      // ← يلغي endGame المجدول
    ...
    saveSession();        // ← يحفظ lives: 0
}
```
و`setInputLocked()` في `js/ui.js` يقفل الإدخال والإرسال والتخطي والتلميح، **لكنه ما يقفل `exitRoundBtn`**، ومفتاح Escape شغال طول الوقت.

**جربتها فعليًا:** حصّلت 20 نقطة، وبعدها ثلاث إجابات غلط، وضغطت Escape مباشرة بعد الثالثة:
```
score before final wrong: 20 | screen now: startScreen | highScore stored: null | session: null
```
النتيجة أن شاشة النهاية ما تظهر، والرقم القياسي ما ينحفظ، والجلسة المحفوظة تُرفض في التحميل لأن `isValidSession` يشترط `lives` بين 1 و3. **الجولة كأنها ما صارت.** وفي تحدي اليوم الوضع أسوأ: `markDailyStarted` يكون قافل اليوم من البداية، و`recordDailyCompletion` ما ينادى، **فتنكسر سلسلة الأيام** بدون أي رسالة للاعب.

النافذة قصيرة، لكن اللاعب اللي يخسر آخر حياة ويعصّب ويضغط «خروج» هو بالضبط اللي بيسويها.

**الحل:** إذا كانت `lives <= 0`، ينهي الخروج اللعبة بدل ما يتركها:
```js
export function abandonRound() {
    if (gameState.lives <= 0) { endGame(); return; }
    ...
}
```
وأضف `exitRoundBtn` إلى `setInputLocked()` عشان يتعطل الزر بصريًا خلال النافذة.

### ب) البنية والحالة: 8/10

التقسيم ممتاز: 14 وحدة، ولكل وحدة مسؤولية واحدة. `game.js` ما يلمس `document` مباشرة، والثوابت مجمّعة (`BASE_POINTS` و`TIMINGS` و`HINTS_PER_ROUND` و`CORRECT_PER_LEVEL`). ودالة `isValidSession()` في `state.js` تتحقق من كل حقل بنوعه ومداه، **ومنها `dailyIndex`** اللي كان ناقص في الجولة الأولى.

#### 🟠 شبكة مشاركة تحدي اليوم تكذب بعد الاستئناف

هذي الشبكة أهم إضافة في PR #4، وفيها خلل في الحفظ. `js/state.js`، في `saveSession()`: اللقطة المحفوظة **ما فيها `dailyMarks`**:
```js
const snapshot = {
    v: SAVE_VERSION, score: ..., lives: ..., dailyIndex: gameState.dailyIndex, savedAt: Date.now()
    // ← dailyMarks غير موجود
};
```
و`resumeDaily()` في `game.js` ما يمرره أصلًا، فـ`resetGameState` يرجعه `[]`.

**جربتها:** حليت 4 أسئلة من تحدي اليوم، وسويت إعادة تحميل، وكمّلت الستة الباقية، وضغطت مشاركة:
```
تحدي الصور · 2026-10-07
10/10
🟩🟩🟩🟩🟩🟩
```
المكتوب **10/10** والمربعات **ستة**. وهذا النص هو اللي يُنشر في القروبات، والإغلاق والاستئناف شائعين جدًا على الجوال، والتصميم نفسه يشجع عليهما.

**الحل:** أضف `dailyMarks` إلى اللقطة، وإلى `isValidSession` (مصفوفة من القيم `correct|hint|wrong|skip` وطولها لا يتجاوز `dailyIndex`)، وإلى `resumeDaily()`. وأضف اختبارًا في `tests/state.test.js` يغطي دورة الحفظ والاستئناف للعلامات.

#### 🟡 سلسلة الأيام تُحسب بتاريخ الانتهاء بدل تاريخ التحدي

`game.js`، في `endGame()`:
```js
const key = todayKey();
dailyStreak = recordDailyCompletion(key, previousKey(key));
```
إذا بدأ اللاعب تحدي الثلاثاء الساعة 11:58 مساءً وخلّصه بعد منتصف الليل، تنحسب له **الأربعاء**: تحدي الأربعاء يبقى مفتوحًا، والثلاثاء ما ينحسب. التاريخ الصحيح محفوظ أصلًا في `currentDailyDate` داخل `state.js`. **الحل:** صدّر getter له واستخدمه هنا وفي `buildShareText()`.

#### 🟡 تعليق قديم يخالف الكود

`state.js` فوق `difficultyForLevel()`:
```js
* ... الآن يصعد اختيار اللاعب درجةً كل مستويين بحد أقصى «صعب».
```
بينما `LEVELS_PER_STEP = 1`، يعني درجة **كل مستوى**. التعليق يضلل أول شخص يحاول يوازن الصعوبة.

### ج) الأصول والحفظ: 7/10

الإيجابيات: `sw.js` يفحص `fresh.ok` قبل تخزين صفحة التنقل، و`healMissingCore()` يرجّع أي أصل أساسي ناقص من المخزن. والخطوط مستضافة ذاتيًا ومقسومة بـ`unicode-range`. والـsprite ملف واحد حجمه 60KB، والـCI يتأكد إنه محدّث.

#### 🟠 ستة أصوات من ثمانية ما تنخزن للأوفلاين، والتوثيق يقول العكس

`docs/تنفيذ-خطة-الإصلاح.md`، البند 6: «البقية… يخزّنها `handleAsset` تلقائياً فيبقى العمل أوفلاين سليماً». وهذا الكلام ما يصح على GitHub Pages.

عنصر `<audio>` يطلب الملف بترويسة `Range: bytes=0-`، والخادم يرد بـ**206 Partial Content**. `handleAsset()` في `sw.js` يفحص `response.ok`، والنتيجة `true` لأن 206 تعتبر ناجحة، وبعدها:
```js
caches.open(CACHE_NAME).then(c => c.put(request, copy)).catch(() => {});
```
و`Cache.put` **يرفض 206 دائمًا**، و`.catch` يبلع الرفض بصمت.

**قسته:** على خادم يدعم Range، بعد بدء جولة وانتظار 4 ثوانٍ لاكتمال `warmSounds()`، كان محتوى المخزن:
```
cached sounds after warm: [ 'click.mp3', 'correct.mp3' ]
sound requests: [ start, wrong, hint, levelup, gameover, highscore ]
```
الطلبات الستة وصلت من الشبكة، لكن ولا واحد منها انخزن. يعني الأوفلاين يعتمد على ذاكرة HTTP المؤقتة في المتصفح، وهذي يمسحها المتصفح متى ما بغى. بعد ما تنمسح، يلعب المستخدم أوفلاين **بدون صوت للخطأ ولا لنهاية اللعبة ولا للمستوى**.

**الحل:** في `warmSounds()`، اجلب الملفات الستة بـ`fetch()` عادي بدون Range، فيرجع الرد 200 ويخزنه `handleAsset`:
```js
Object.values(soundFiles).forEach(p => fetch(p).catch(() => {}));
```
والأمتن من هذا أن يتجاهل `handleAsset` أي رد 206، ويجلب نسخة كاملة يخزنها. وصحّح الجملة في وثيقة التنفيذ.

#### 🟡 الملفات الصوتية نفسها ما زالت مضخّمة

`wrong.mp3` حجمه 104K، و`hint.mp3` حجمه 80K، لنغمات مدتها ثوانٍ. هذا البند كان مفتوحًا في الجولة الأولى وما زال مفتوحًا. المسار الحرج عولج (أول تحميل صار فيه 16K صوت فقط)، لكن أول جولة تجلب في الخلفية قرابة 330K. إعادة الترميز إلى 64kbps أحادي تحتاج أمر `ffmpeg` واحد.

#### 🟡 الأوفلاين يعتمد على تذكّر رفع رقم الإصدار يدويًا

`sw.js`: `CACHE_NAME = 'image-challenge-v4'`. ملفات JS وCSS تُخدم بأسلوب «المخزن أولًا»، فإذا عُدّل `game.js` بدون رفع الرقم، يأخذ اللاعبون العائدون `index.html` جديدًا (لأن التنقل يمر بالشبكة أولًا) مع JS قديم. السجل يبين أن الرقم رُفع في كل تعديل (من v1 إلى v4)، لكن هذا يعتمد على الذاكرة. **الحل الرخيص:** خطوة في الـCI تفشل إذا تغيّر شيء من `CORE_ASSETS` بدون أن يتغير `CACHE_NAME`، أو اشتقاق الاسم من hash الملفات وقت النشر.

### د) الأساسيات: 8/10

- **الاختبارات:** 80 اختبارًا تغطي `arabic` و`daily` و`state` و`questions` ونقاط `game`، وكلها تنجح. لكن **الخطأين البرتقاليين في هذا القسم كلاهما في كود التدفق** (`onWrong` و`abandonRound` و`resumeDaily` و`saveSession` في الوضع اليومي)، وهذا الكود بدون أي اختبار. السبب أن `game.js` يستورد `ui.js` ويلمس `elements`، فصعب يتحمّل تحت Node. **الحل:** حقن `ui` كوسيط، أو بيئة DOM خفيفة مثل `linkedom`، ثم اختبار التسلسلات: «خطأ أخير ثم خروج»، و«يومي: حفظ ثم استئناف ثم مشاركة».
- **التوثيق:** التعليقات تشرح **ليش** وليس **وش**، وهذا مستوى ممتاز. والاستثناء الوحيد التعليق القديم المذكور فوق.
- **DRY:** `DIFFICULTY_LABELS` مكررة في ثلاثة ملفات (`game.js` و`main.js` و`ui.js`). ومنطق «خسارة حياة ثم نهاية أو كشف الإجابة» مكرر بين `onWrong` و`handleTimeout` و`skipQuestion`، ولو كان في دالة واحدة كان الخلل الأول ينصلح في مكان واحد.
- **CI:** `concurrency: group: pages` معرّف على مستوى الملف، فتشغيلات اختبار الـPR تنتظر في نفس الطابور مع النشر. انقله إلى وظيفة `deploy`.

## 2. تصميم اللعبة وتجربة اللاعب (40%): **7.5/10**

### أ) الإحساس باللعب: 7.5/10

**الموجود في الكود:** وميض أخضر وأحمر (`correct-anim` و`wrong-anim`)، واهتزاز يحترم `prefers-reduced-motion` في `vibrate()`، وثمانية أصوات، وكونفيتي عند الرقم القياسي، وتوست بالنقاط ومضاعف السلسلة، وكشف الإجابة كاملة داخل البطاقة عند الخطأ (`revealAnswer`). والفاصل بين الخطأ والسؤال التالي 2.2 ثانية، وهي مدة كافية لقراءة الإجابة. أي إن رد الفعل البصري والسمعي موجود لكل فعل مهم.

⚠️ هل التجربة «حلوة» فعلًا أو لا؟ هذا ما يُحكم عليه من الكود. اللي يقدر يقاس هو وجود الآليات، وهي موجودة.

🟡 **ملاحظة من اللقطات:** على 320×568 لاحظت التوست «+60 نقطة · لغز جديد» ظاهر **فوق** كشف «الإجابة الصحيحة» لسؤال غلط جاء بعده. السبب أن التوست يبقى 2.6 ثانية والسؤال التالي يظهر بعد 0.9 ثانية. الحل: `hideToast()` في بداية `loadQuestion()`.

### ب) التوازن ومنحنى الصعوبة: 6.5/10

#### 🟠 اختيار «سهل» صار بلا معنى بعد 10 إجابات

`state.js`:
```js
export const LEVELS_PER_STEP = 1;
export const CORRECT_PER_LEVEL = 5;
```
**قسته في جولة فعلية بعد اختيار «سهل»:**
```
المستوى 1 · سهل  (×4) | المستوى 2 · متوسط (×5) | المستوى 3 · صعب ...
```
بعد **5** إجابات صحيحة تصير الصعوبة متوسط، وبعد **10** تصير صعب، ويقصر المؤقت من 30 ثانية إلى 20. اللاعب اللي اختار «سهل»، وغالبًا هو صغير في السن أو جديد على الأمثال، ما يقدر يبقى عليه. التصعيد نفسه فكرة صحيحة (كان «المستوى» في الجولة الأولى رقمًا بدون أثر)، لكن صار **يتجاوز** اختيار اللاعب بدل ما يحترمه.

**الحل:** خلّ اختيار اللاعب هو الأرضية، وبعدها درجة واحدة كحد أقصى فوقها، أو خلّ «سهل» ثابتًا تمامًا:
```js
const cap = Math.min(start + 1, DIFFICULTIES.length - 1);
return DIFFICULTIES[Math.min(start + steps, cap)];
```

#### 🟡 فئتا «شعر» و«إسلامية» صغيرتان وتتكرر أسئلتهما

العدد المقيس: شعر **17** لغزًا (6 سهل و6 متوسط و5 صعب)، وإسلامية **18** (6 لكل مستوى). اللاعب اللي يختار «شعر» يستنفد مجموعة مستواه بعد 6 أسئلة، وتبدأ الأسئلة تتكرر بعد قرابة 15 سؤالًا عبر المستويات، وهذا أقصر من جولة واحدة طويلة. الحل الوحيد هنا إضافة محتوى، أو على الأقل تنبيه بجانب الفئة: «17 لغزًا».

🟢 **اللي ما يحتاج تعديل:** الخصم على التلميح (−3 والحد الأدنى 5)، والتلميحات الخمس محسوبة على الجولة كاملة، والتخطيان المجانيان، ومضاعف السلسلة (×1.5 عند 3، و×2 عند 5). هذي أرقام متوازنة ولا أرى فيها استراتيجية مهيمنة. **قابلية حلّ الألغاز نفسها** (الـ86 لغزًا اللي أعيد تأليفها) ما يُحكم عليها إلا بلاعب حقيقي، والمقياس الوحيد اللي أقدر أطلعه من الكود: 10 ألغاز فقط فيها 2.5 كلمة أو أكثر لكل أيقونة، وكل تسلسلات الأيقونات فريدة (143 من 143).

### ج) التعريف باللعبة: 9/10

`js/tutorial.js` فيه لغز تفاعلي واحد مضمون (التفاحة والشجرة) قبل أي إعداد. المحاولة الأولى الخاطئة تطلع تلميحًا، والثانية تكشف الإجابة وتكمل، فما ينحبس اللاعب. وزر التخطي موجود. والإعدادات المتقدمة مخفية خلف «خيارات اللعب» في أول زيارة (`setupSettingsDisclosure`)، فالشاشة الأولى فيها قرار واحد بس: كلاسيكي أو تحدي اليوم. هذا تعريف بالممارسة وليس جدار نص.

### د) الواجهة والمظهر: 7/10

**العربية وRTL، فحصتها فعليًا:** `<html lang="ar" dir="rtl">`. وCSS ما فيه ولا `margin-left` أو `padding-right` فيزيائية، والاستثناء الوحيد `left: 50%` للتوسيط، وهذا محايد للاتجاه. وفيه 6 استخدامات منطقية (`inset-inline` و`margin-inline` و`padding-inline`). وسهم «تخطي» مكتوب `❮` باتجاه القراءة الصحيح. وخط Tajawal مستضاف ذاتيًا ومقسوم عربي ولاتيني. وتوحيد الكتابة في `normalizeArabic()` يغطي الهمزات والتاء المربوطة والألف المقصورة والتشكيل، ونطاقاته مكتوبة بحروف عربية مباشرة. (التعليق فوقها يقول «كُتبت برموز `\u`»، وهذا غير صحيح. تفصيل بسيط، لكنه تعليق يخالف الكود مرة ثانية.)

**المقاسات (مقيسة):** ما فيه تمرير أفقي على أي مقاس. وأيقونة اللغز 82px على 390، و76px على 360، و67px على 320، وكلها مقروءة.

🟡 **البطاقة ما زالت تبتلع الشاشة.** `css/styles.css`، في `.question-card`: `flex: 1;` ما زال موجودًا. على 390×844 ارتفاع البطاقة **502px** والمحتوى داخلها **132px**، يعني قرابة 74% فراغ (رقم «49%» في وثيقة التنفيذ نسبة امتلاء حاوية الأيقونات، وليس البطاقة). المشكلة العملية مع لوحة المفاتيح: حقل الإجابة يبدأ عند 664px والأيقونات تبدأ عند 296px. على جهاز فيه لوحة مفاتيح بارتفاع 300px تقريبًا، يمكن ما تبين الأيقونات والحقل مع بعض. هذا يحتاج تجربة على جهاز حقيقي، **وما يُحكم عليه من المتصفح بلا رأس**. الحل المقترح: `flex: 0 1 auto` للبطاقة مع حد أدنى معقول.

🟡 **على 320×568 أزرار الزاوية تغطي المحتوى عند التمرير.** طول الصفحة 581px أطول من الشاشة، وكشف الإجابة يطوّلها أكثر. والأزرار `position: fixed` فتنسحب فوق البطاقة والقلوب (واضح في لقطة الوضع الليلي). الإصلاح السابق أضاف `padding-top` فقط، وهذا ينفع والصفحة في أعلاها. الحل: `position: absolute` داخل الشاشة بدل `fixed`، أو خلفية للشريط.

🟡 **إمكانية الوصول:** `#timerBar` عليه `role="progressbar"` لكن **بدون `aria-valuenow`**، فقارئ الشاشة يعلن شريط تقدم بدون قيمة. أضف `aria-valuemin="0"` و`aria-valuemax` و`aria-valuenow` في `paint()` (بالثواني الصحيحة، عشان ما يتحدث في كل إطار). وألوان الوميض (أخضر للصح وأحمر للغلط) معها نص كشف الإجابة، فما تعتمد على اللون وحده، وهذا جيد لعمى الألوان. وفيه كتم للصوت وشريط لمستواه.

### هـ) دورة الاستمرارية: 8/10

فيه أكثر من سبب يرجّع اللاعب: **دفتر الأمثال** (143 لغزًا، مع تصفية بالفئة)، و**سلسلة الأيام** ظاهرة على شريحة التحدي، و**شبكة المشاركة** بدون كشف إجابات، والرقم القياسي وأفضل سلسلة. وبعد الخسارة، زر «العب مرة أخرى» يبدأ فورًا بنفس الإعدادات (`lastRoundOptions()`)، فبين نهاية الجولة وبداية الجديدة ضغطة وحدة.

الثغرتان هنا هما نفس الخطأين التقنيين: الشبكة تكذب بعد الاستئناف، والسلسلة ممكن تنكسر بصمت. وهذي أهم آليات العودة في اللعبة.

## 6. سؤال الحكم النهائي

**«لو لعبت هذي اللعبة 10 دقائق، هل بأكمل؟ وليش؟»**

**أيه، بأكمل.** وهذي المرة واثق أكثر من الجولة الأولى.

أول دقيقة واضحة: لغز التفاحة يعلّمني اللعبة بدون ما أقرأ شيء، وبعده شاشة فيها قرار واحد. الألغاز صارت تُقرأ كجمل (عين، عين، ×، قلب: «بعيد عن العين بعيد عن القلب») وليست كيس رموز. ولما أغلط أشوف الإجابة كاملة وأتعلم منها، وهذي في رأيي أحلى لحظة في اللعبة لأنها تذكّرني بمثل كنت ناسيه. ودفتر الأمثال وسلسلة اليوم يعطوني سببًا أرجع بكرة.

**أقوى نقطة:** المحتوى نفسه، يعني 143 مثلًا وحكمة وبيتًا بنكهة سعودية وخليجية، ومعه منظومة عودة متكاملة (دفتر وسلسلة وشبكة مشاركة) بدون خادم ولا حساب. وتحت هذا كله كود نظيف ومعلّق بعناية نادرة.

**أضعف نقطة تحتاج إصلاحًا فوريًا:** **مسار حفظ تحدي اليوم.** هو أكثر نمط فيه سبب للرجوع والمشاركة، وهو اللي فيه الخللين: أشارك نتيجة تكذب (10/10 بستة مربعات)، أو أخسر سلسلتي لأني ضغطت «خروج» بعد آخر غلطة. اللاعب ما يسامح على الآليات اللي تحسب تقدّمه.

**ما لا يمكن الحكم عليه من الكود:** هل يقدر لاعب يعرف المثل يوصل للحل خلال 30 ثانية؟ وهل البطاقة والحقل يبانون مع بعض فوق لوحة المفاتيح على جهاز حقيقي؟ الأول يحتاج خمسة لاعبين حقيقيين، والثاني يحتاج تجربة على جوال.
