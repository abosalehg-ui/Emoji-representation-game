## 0. تحديد نوع اللعبة والمحرك

| البند | القيمة |
|---|---|

لا فيزياء ولا Object Pooling ولا كشف تصادم — لا حلقة لعب أصلاً، بل دورة سؤال/جواب.

**ما سأحاكمه بصرامة:** جودة اللغز نفسه (هو كل اللعبة)، ووضوح الواجهة أثناء اللعب، وصمود التطبيق على شبكة الجوال.

## 1. المراجعة التقنية والهندسية (40%) — **7.5/10**

### أ) حلقة اللعبة والأداء

المشروع نجا من الأخطاء القاتلة الشائعة في هذي الفئة، وهذا يستحق التسجيل صراحةً:

`js/timer.js` — المؤقت يقيس الزمن الحقيقي لا عدد النبضات:
```js
remaining = total - (performance.now() - startedAt) / 1000;
```
هذا صحيح تماماً. النسخة المبنية على `setInterval` بخصم ثابت كانت تنحرف وتتوقف في التبويب الخلفي.

`js/confetti.js` — السرعات بالبكسل/**ثانية** مع تحديد للخطوة:
```js
const dt = Math.min((now - last) / 1000, 0.05);
p.x += p.vx * dt;
```
سليم: لن يسقط الكونفيتي بسرعة مضاعفة على شاشة 120Hz.

`js/game.js` — سجل مؤقتات معلّقة يُلغى عند النهاية (`pending` + `cancelPending`) — يمنع ظهور سؤال فوق شاشة النهاية. سليم.

**لكن هنا أخطر ما في المشروع كله:**

#### 🔴 التطبيق يموت صامتاً إذا تعثّر طلب الـsprite

`js/main.js` — في `boot()`:
```js
cacheElements();
initTheme();
loadSounds();

await loadSprite();   // ← لا مهلة زمنية، ولا Promise.race

setSoundIcon();
// ... كل ربط الأحداث يأتي بعد هذا السطر
elements.playBtn?.addEventListener('click', startFromControls);
```
و`js/icons.js` يستدعي `fetch(SPRITE_URL)` بلا `AbortSignal.timeout`.

**اختبرته فعلياً:** حجزت طلب `assets/sprite.svg` بحيث لا يُستجاب له (محاكاة شبكة جوال متعثرة لا شبكة مقطوعة)، ثم انتظرت 8 ثوانٍ وضغطت زر اللعب:

```
screen after clicking PLAY with hung sprite: startScreen
sound icon rendered: 0
```

النتيجة: **الشاشة الأولى تظهر كاملة ومرتّبة، والأزرار كلها ميتة.** لا رسالة خطأ، لا مؤشر تحميل، لا شيء.
اللاعب يرى لعبة سليمة المظهر ويضغط زر اللعب فلا يحدث شيء — وهذا أسوأ من شاشة بيضاء صريحة، لأنه يبدو عطلاً في جهازه.

لاحظ أن مسار الفشل **الصريح** يعمل بامتياز: عند 404 يرجع `fallbackStaticIcons()` إلى `<img>` وتعمل اللعبة (اختبرته: 27 أيقونة `<img>` وشاشة التعريف ظهرت). المشكلة حصراً في **التعليق بلا مهلة**، وهي أشيع من الـ404 على شبكات الجوال.

**الحل:**
```js
// icons.js
const res = await fetch(SPRITE_URL, { cache: 'force-cache', signal: AbortSignal.timeout(3000) });
```
وفي `main.js` اجعل الـsprite تحسيناً لا شرطاً للإقلاع:
```js
loadSprite().then(ok => { if (ok) repaintStaticIcons(); });  // بلا await
```
الأيقونات تظهر متأخرة نصف ثانية — لكن اللعبة **تعمل**.

```js
for (const [key, path] of Object.entries(soundFiles)) {
```

### ب) البنية والحالة

التقسيم ممتاز: 14 وحدة، كل واحدة بمسؤولية واحدة، ومنطق اللعب (`game.js`) مفصول عن الرسم (`ui.js`) فصلاً حقيقياً — `game.js` لا يلمس `document` إطلاقاً.

الثوابت مجمّعة لا مبعثرة، وهذا يبقي الموازنة ممكنة:
```js
const BASE_POINTS = { easy: 10, medium: 20, hard: 30 };
const TIMINGS = { afterCorrect: 900, afterWrong: 2200, afterSkip: 1400, ... };
```

**قفل الإرسال يعمل فعلاً** — تحققت منه بالتجربة لا بالقراءة: ملأت الإجابة الصحيحة وضغطت الإرسال 6 مرات متتالية:
```
score before/after 6 rapid submits: 0 20
```
20 نقطة لا 120. سليم.

**التحقق من ملف الحفظ ممتاز** — `state.js` في `isValidSession()` يفحص كل حقل بنوعه ومداه، ويُنظّف المفتاح التالف بدل أن يعلق على شاشة تحميل. هذا مستوى نضج نادر في مشاريع بهذا الحجم.

🟡 **لكن `dailyIndex` غاب عن التحقق.** في `state.js`:
```js
return int(s.score, 0, 10_000_000)
    && int(s.lives, 1, 3)
    // ... كل شيء تقريباً — إلا dailyIndex
```
و`resumeDaily()` يستهلكه مباشرة: `dailyIndex: saved.dailyIndex`. ملف محفوظ فيه `dailyIndex: "abc"` يُمرَّر كما هو. لن ينهار شيء (`getNextQuestion` يرجّع `undefined` فتنتهي الجولة)، لكنه ثقب في جدار كامل بقية بنائه. أضف `&& int(s.dailyIndex, 0, 50)`.

### ج) الأصول والحفظ

**العمل أوفلاين ممتاز — اختبرته:** ثبّتّ الـService Worker، قطعت الشبكة، أعدت التحميل:
```
C) offline reload -> screen: introScreen | sprite symbols in DOM: 206
```
206 رمز أيقونة من المخزن. اللعبة تعمل كاملة أوفلاين. هذا وعد الـPWA وقد أُوفي به.

#### 🟠 أي صفحة خطأ تُخزَّن مكان التطبيق نفسه

`sw.js` — في `handleNavigation()`:
```js
const fresh = await fetch(request);
const cache = await caches.open(CACHE_NAME);
cache.put('./index.html', fresh.clone()).catch(() => {});   // ← بلا فحص fresh.ok
return fresh;
```
`Cache.put` لا يرفض الاستجابات غير الناجحة (يرفض 206 فقط). فإذا ردّ الخادم يوماً بـ404 أو 502 أو صفحة صيانة، **تُخزَّن تلك الصفحة مكان `index.html`** ويستمر عرضها أوفلاين إلى الأبد — والـ`.catch(() => {})` يبتلع كل أثر.

المفارقة أن `handleAsset()` في نفس الملف يفعلها صح: `if (response.ok)`. تناقض داخل ملف واحد.

**الحل:**
```js
if (fresh.ok) cache.put('./index.html', fresh.clone()).catch(() => {});
```

🟡 **مسار الأيقونات البديل لا يعمل أوفلاين.** `icons.js` يرجع عند الفشل إلى `assets/images/<name>.svg`، لكن `CORE_ASSETS` في `sw.js` لا يخزّن مجلد `assets/images` إطلاقاً. فلو فشل الـsprite **وكان اللاعب أوفلاين**، البديل يفشل هو الآخر. والأسوأ: 836 كيلوبايت من ملفات SVG المنفردة تُنشر مع الموقع لخدمة مسار لا يشتغل في نصف الحالات التي وُجد لأجلها.

اختر واحداً: إما تخزّن الملفات المنفردة أوفلاين، أو تحذفها من النشر وتعتمد على الـsprite وحده (60KB) وتقبل أن فشله = لا أيقونات.

🟡 **`stopConfetti()` مُصدَّرة ولا تُستدعى في أي مكان.** بحثت في كل المصدر:
```
js/game.js:15:import { triggerConfetti } from './confetti.js';
js/game.js:451:        triggerConfetti();
```
`stopConfetti` كود ميت. والأثر ظاهر في لقطة الشاشة: بعد رقم قياسي، الكونفيتي يستمر متساقطاً فوق **دفتر الأمثال وشاشة البداية ولوحة الإعدادات** لثوانٍ طويلة (`vy` بين 120 و360 بكسل/ثانية، والجسيمات تبدأ فوق الشاشة بارتفاع كامل — أي حتى **14 ثانية** على شاشة طويلة) بينما اللاعب يحاول قراءة دفتره. اربط `stopConfetti()` بـ`showScreen()`.

🟡 **`skipWaiting()` + `clients.claim()` عند التثبيت** يجعلان النسخة الجديدة تستولي على الصفحة في منتصف الجلسة، والصفحة قد تكون حمّلت وحدات JS من المخزن القديم الذي حُذف للتو في `activate`. الاستيراد الديناميكي في `endGame()`:
```js
import('./icons.js').then(({ setIcon }) => ...)
```
قد يصطدم بذلك. لعبة صغيرة فالخطر محدود — لكن الصواب هو انتظار إعادة التحميل بدل `skipWaiting` الفوري.

### د) الأساسيات

**الاختبارات:** 27 اختباراً تمر كلها، وهي جيدة النوعية — تغطي التطبيع العربي ومطابقة الإجابات وسلامة قاعدة الأسئلة، وتوثّق الثغرات المُصلحة (تكرار الكلمة الصحيحة، الشدّة قبل المقارنة).

هذا أنفع من أي README.

## 2. تصميم اللعبة وتجربة اللاعب (40%) — **6/10**

هنا يفترق المشروع عن نفسه: **الغلاف ممتاز، واللعبة داخله ضعيفة.**

### أ) الإحساس باللعب (Game Feel)

الآليات موجودة فعلاً في الكود، وهذا ما يمكن الحكم عليه:

| الآلية | الحالة |
|---|---|
| اهتزاز الجهاز | ✅ `ui.js` → `vibrate(30)` صح، `vibrate([40,60,40])` خطأ — ويحترم `prefers-reduced-motion` |
| حركة بصرية | ✅ `correctBounce` و`shake` على بطاقة اللغز |
| صوت لكل فعل | ✅ 8 مؤثرات، ولكلٍّ مستوى نسبي (`RELATIVE = { click: 0.45 }`) — تفصيل يدل على أذن |
| احتفال بالرقم القياسي | ✅ كونفيتي + صوت مخصص |
| منحنيات Easing | ✅ في CSS |

⚠️ **الحكم النهائي على الإحساس باللعب يحتاج تجربة بشرية فعلية** — الآليات موجودة، لكن هل «تُحسّ» صحيحة لا يُقاس من الكود ولا من لقطة شاشة.

**ما أستطيع الجزم به:** توقيت التغذية الراجعة **بطيء**. `TIMINGS.afterWrong = 2200` — أي 2.2 ثانية جمود بعد كل خطأ. في لعبة ألغاز الإيقاع فيها ذهني لا حركي، هذا مقبول للقراءة، لكن مع `afterSkip = 1400` و`afterCorrect = 900` تشعر الجولة بأنها متقطعة. جرّب `afterWrong: 1600`.

### ب) 🔴 المشكلة الأكبر: كثير من الألغاز **غير قابل للحل من الصور**

هذي هي الملاحظة التي لو أُصلحت واحدةً فقط، فلتكن هي. اللعبة كلها تقوم على أن تسلسل الأيقونات يقود إلى العبارة. في جزء كبير من قاعدة الأسئلة **لا يقود إليها إطلاقاً**.

قياسات فعلية على الـ143 لغزاً:

| المقياس | القيمة |
|---|---|
| متوسط الأيقونات لكل لغز | 2.91 |
| أكثر الأيقونات تكراراً | `x-mark` ×13، `eye` ×10، `fire` ×10، `wind` ×10، `sunrise` ×9، `house` ×9، `falcon` ×8، `crown` ×8 |
| ألغاز تلميحها الأول يكشف المصدر مباشرة | **26 لغزاً** |
| وسيط طول الإجابة | 5 كلمات (وأطولها 12) |

أمثلة مأخوذة من `js/questions.js` كما هي:

```js
{ icons: ["moon", "crescent-moon", "sun"], answer: "الصبر مفتاح الفرج" }
{ icons: ["mountain", "wave", "tornado", "fire"], answer: "من صبر ظفر" }
{ icons: ["falcon", "nest", "mountain-sunrise"],
  answer: "لا تحسبن المجد تمراً أنت آكله لن تبلغ المجد حتى تلعق الصبرا" }
{ icons: ["sun", "palm-tree"], answer: "كل شي بوقته حلو" }
{ icons: ["sheep", "sheep"], answer: "الغنم ما تنطح إلا من روسها" }
{ icons: ["prayer-beads", "mosque", "crescent-moon", "sparkles"],
  answer: "رب اشرح لي صدري ويسر لي أمري" }
```

قمر + هلال + شمس → «الصبر مفتاح الفرج»؟ لا يوجد مسار ذهني من هذي الصور إلى تلك العبارة. الصور تصف **مزاج** الحكمة (مرور الوقت) لا **ألفاظها**. وصقر + عش + جبل عند الشروق → بيت من 12 كلمة للمتنبي: مستحيل بلا معرفة سابقة بالبيت نفسه **وتخمين** أنه هو المقصود من بين مئة بيت يصلح لنفس الصور.

قارنها بالألغاز التي **نجحت** — وهي في اللعبة نفسها، فالمؤلف يعرف كيف تُصنع:
```js
{ icons: ["apple", "tree"], answer: "التفاحة لا تسقط بعيداً عن الشجرة" }   // ✅ حرفي
{ icons: ["water-drop", "rock"], answer: "قطرة الماء تثقب الحجر" }         // ✅ حرفي
{ icons: ["writing-hand", "sword"], answer: "القلم أقوى من السيف" }        // ✅ حرفي
{ icons: ["eye", "eye", "x-mark", "anatomical-heart"],
  answer: "بعيد عن العين بعيد عن القلب" }                                  // ✅ نحو رمزي حقيقي
```
هذي الأربعة قابلة للحل لأن كل أيقونة **كلمة في الجملة**، والترتيب نحو.

**الدليل الحاسم أن الصور لا تعمل: التلميحات تحمل الحل كله.** 26 لغزاً تلميحه الأول حرفياً «بيت للمتنبي» أو «حديث نبوي» أو «آية قرآنية». هذا اعتراف ضمني بأن الصور وحدها لا تكفي — فوُضع المصدر في التلميح لينقذ الموقف. النتيجة أن الوضع الصعب ليس لغزاً بل **اختبار حفظ**: إما تعرف البيت فتكتبه، أو لا تعرفه فلا تصل إليه بأي قدر من التفكير.

**الحل — ولا يحتاج إعادة كتابة، بل مراجعة بيانات:**

1. **قاعدة صارمة: كل أيقونة = كلمة أو مقطع في الجملة، والترتيب هو الترتيب.** لو ما قدرت تخريج اللغز على هذي القاعدة، فالعبارة غير صالحة للعبة — احذفها ولا تُرقّعها بتلميح.
2. **ارفع متوسط الأيقونات من 2.91 إلى 4–5** للعبارات الطويلة. إجابة من 12 كلمة خلف 3 أيقونات ظلم صريح.

🟠 **«المستوى» شارة بلا معنى ميكانيكي.** في `game.js`:

```html
      content="default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; connect-src 'self'">
```
اللعبة لا تتصل بأي مصدر خارجي أصلاً، فالسياسة لن تكسر شيئاً.

🟡 **صلاحيات CI أوسع من اللازم في تشغيلات الـPR** (مذكورة أعلاه). المخاطرة عملياً منخفضة (رموز الـfork للقراءة فقط)، لكن المبدأ يقتضي حصر `pages: write` في وظيفة `deploy`.

## 4. الدرجة الإجمالية المرجّحة

| الناحية | الدرجة | الوزن | المساهمة |
|---|---|---|---|
| تقنية وهندسية | 7.5/10 | 40% | 3.00 |
| تصميم اللعبة و UX | 6.0/10 | 40% | 2.40 |
| أمن ومكافحة غش | 8.0/10 | 20% | 1.60 |
| **الإجمالي** | | | **7.0/10** |

**الحساب صراحةً:** (7.5 × 0.40) + (6.0 × 0.40) + (8.0 × 0.20) = 3.00 + 2.40 + 1.60 = **7.00**

**قراءة الدرجة:** مشروع أعلى بوضوح من المتوسط في هذي الفئة. البنية والتوثيق والتعامل مع RTL ومطابقة العربية على مستوى احترافي حقيقي. ما يخفض الدرجة ليس رداءة تنفيذ، بل أن **اللعبة داخل الغلاف الممتاز أضعف من الغلاف**: كثير من الألغاز غير قابل للحل، والنقاط غير مرئية أثناء اللعب، والتقدّم بلا مضمون ميكانيكي. وهذي كلها قابلة للإصلاح بلا إعادة كتابة.

## 6. سؤال الحكم النهائي

> **لو لعبت هذي اللعبة 10 دقائق، هل بأكمل؟**

**نعم أكمل العشر الدقائق — ولا أعود بعد بكرة.** وهذي إجابتان مختلفتان، وكلٌّ منهما لسبب.

**ليش أكمل العشر:** التعريف يمسك بي فوراً — لغز واحد (تفاحة + شجرة) أحلّه بنفسي في خمس ثوانٍ فأفهم اللعبة بلا كلمة شرح. أكتب «التفاحه ما تسقط بعيد عن الشجره» بلا تشكيل وبإملاء متساهل **فتُقبل**، وهذي اللحظة تحديداً هي التي تقرّر إن كنت سأكمل أو أغلق: لعبة عربية تفهم أن الناس ما يكتبون الهمزات صح. الشكل نظيف، الوضع الليلي جميل، الأصوات مضبوطة، وحين أخطئ تظهر الإجابة كاملة فأتعلّم شيئاً. عشر دقائق ممتعة بلا شك.

**ليش ما أعود:** لأن في الدقيقة السابعة تقريباً يجيني لغز مثل قمر + هلال + شمس، وأحدّق فيه، وأجرّب، وأخسر حياة، ثم تظهر الإجابة: «الصبر مفتاح الفرج». وأنا أعرف هذا المثل تماماً — **لكن ما كان فيه طريق من الصور إليه**. ولما يتكرر هذا ثلاث أو أربع مرات، أتوقف عن التفكير وأبدأ التخمين، ثم أضغط «تلميح» فيقول لي «بيت للمتنبي» فأعرف أن الصور ما كانت تعمل من الأصل. اللعبة تتحول من لغز إلى اختبار حفظ، وأنا لم آتِ لأُختبر بل لأحلّ.

وقبل ذلك بقليل ألاحظ شيئاً أصغر لكنه يقضم المتعة: أجاوب صح، أسمع الصوت، يومض «+20 نقطة» ثانيتين ثم يختفي… وأرفع عيني للأعلى لأرى مجموعي فأجد **زر الصوت جالساً فوقه**. ما أعرف كم صار عندي. اللعبة تسألني أن أتنافس على رقم لا تريني إياه.

**أقوى نقطة:** `js/arabic.js` — مطابقة الإجابات العربية. هذي أصعب قطعة في المشروع كله وأُنجزت بامتياز: تسامح مع التشكيل والهمزة والتاء المربوطة، وترفض حشو الكلمات، وتقيس التغطية والدقة معاً. اختبرتها على 27 حالة فما أخطأت في واحدة. ولولاها لكانت اللعبة غير قابلة للعب أصلاً — وأكثر الألعاب العربية تسقط هنا بالضبط.

**أضعف نقطة تحتاج إصلاحاً فوراً:** **الألغاز نفسها.** ليست مشكلة كود ولا هندسة — الهندسة هنا جيدة جداً. المشكلة أن العقد بين اللعبة واللاعب («الصور تقودك إلى العبارة») مكسور في جزء كبير من الـ143 لغزاً. أصلح هذا وحده وترتفع اللعبة من «تجربة لطيفة» إلى «لعبة يوصي بها اللاعب غيره».

**ما لا أستطيع الحكم عليه من الكود ومن التشغيل الآلي:**
- هل يقنع منحنى صعوبة تحدي اليوم لاعباً بشرياً؟ (البنية سليمة — 4/4/2 صاعد — لكن الإحساس يحتاج تجربة فعلية)
- هل توقيت التغذية الراجعة (900/2200/1400 مللي ثانية) يُشعر بالسلاسة أم بالتقطّع؟ رقمياً بطيء، لكن الحكم النهائي للأصابع لا للحاسبة
- هل الأيقونات مفهومة لجمهور عربي حقيقي؟ لاحظت أن عدداً منها ملتبس عندي في اللقطات (`ship` تُقرأ كطاولة، `sunrise` كمصباح) — لكن هذا حكم فرد واحد ويحتاج اختبار مستخدمين، لا رأي مراجع

### كلمة أخيرة

هذا مستودع مكتوب بعناية ظاهرة: تعليقات تشرح *لماذا* لا *ماذا*، وتوثّق العطل الذي عولج؛ ووحدات مفصولة بمسؤوليات نظيفة؛ وتعامل مع RTL والعربية أنضف مما أراه عادةً في مشاريع أكبر منه بكثير؛ وصفر اعتماديات إنتاج؛ و27 اختباراً تمر. الأساس الهندسي هنا **جاهز لحمل لعبة ممتازة**.

الفجوة ليست في البناء بل في المحتوى: قاعدة الألغاز لم تُراجَع بنفس الصرامة التي رُوجع بها الكود. أنصح بأن تكون الجولة القادمة **جولة بيانات لا جولة كود** — امشِ على الـ143 لغزاً واحداً واحداً بقاعدة «أيقونة = كلمة»، واحذف ما لا ينضبط بلا تردد. لغز واحد جيد أنفع من خمسة مبهمة، والحذف هنا مكسب لا خسارة.
